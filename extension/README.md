## Rules
- Preserve all existing files under `evidence/`, `theory/`, `prompts/`, and `manuscript/`. No edits, deletion or overwrite outside `extension/` without a separate explicit request.
- Retain every existing manuscript section; add related `\\subsection{}` or `\\subsubsection{}` within its respective existing section, never add a Section 20 or claim the extension is the original 20-stage programme.
- Maintain a verbatim snapshot of the latest available eight-page TeX manuscript inside `extension/manuscript/original/` before any integration; if not accessible in GitHub, obtain its exact bytes from an attached artifact, not a reconstructed approximation. Mark the snapshot gate blocked until secured.
- A prompt is permission to investigate and may yield NO-GO; never fabricate theorem novelty, GitHub Actions runs, simulated outcomes, data, experimental advantages, field repair measurements or 100/100 verdict.
- Annotate every file and metric as PLANNED / EXECUTED / VERIFIED / BLOCKED. Preserve all negative findings. A graph from a real topology with synthetic failures is a synthetic-failure experiment.
- After EACH stage: commit all new or revised extension paths to GitHub, independently re-fetch every changed path and compare SHA and content, update `extension/PROGRESS.md`, then STOP and ask for explicit author approval to run the next stage.
- If scientific gates fail, revise target claims instead of inventing results; keep current original-theorem NO-GO pending independent evidence.
- Use `extension/src/`, `extension/tests/`, `extension/experiments/`, `extension/data/`, `extension/results/`, `extension/theory/`, `extension/evidence/`, `extension/manuscript/`, `extension/validation/`, `extension/prompts/`. Code and workflows are proposed, not yet implemented.

## Main research goal
Decision-Sufficient Adaptive Network Repair with Repair-Dependent Observability. Study whether repair-induced changes in physically feasible measurements and finite intervention budgets confer a nontrivial, verifiable advantage over direct baselines in exact fault diagnosis, overlapping decision-region determination and sequential planning. Strongest intended application: telecom backbone restoration, followed conditionally by SDN emulation and packet simulation.
